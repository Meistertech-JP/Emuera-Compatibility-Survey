# DO・LOOP：BREAKと偽の終了条件の保存観測

[English](README.md) · [選択観測JSON](observation.json) · [元資料のSHA-256](source-digests.json)

対象は `DOLOOP259_BREAK_SUPPRESSION` の有限条件です。原票はこの一つのケースを `command_or_syntax:DO`、`command_or_syntax:LOOP`、`structural_syntax:DO`、`structural_syntax:LOOP` に関連付け、判定を **matched_scoped** としています。4件の別実行や各対象全体の互換性を示すものではありません。

## 条件と結果

空のCSV、同一のERB・ERH・設定を使う共有fixtureで、本家 Emuera 1.824 +v24を2回、PyEmuera 3.0.0を1回実行した保存記録です。ERBでは最初のDO内で2回目の本体到達時にBREAKし、別のDOでは本体実行後に偽を返すLOOP条件を評価します。ガード関数は偽を返し、呼ばれた場合に除算を行う関数への到達を防ぐ構成です。最初に `RESULT=701`、`RESULTS=sentinel259` としています。

下表は3実行の保存履歴で共通の値です。列中の変数はそれぞれ本体回数B/F、最初／後の条件関数の回数BC/FC、ガード回数G、危険関数回数Xです。

| 観測点 | 本家2回 | Py 1回 |
|---|---|---|
| 最初のDO本体 | `B=1 BC=0 X=0` → `B=2 BC=1 X=0` | 同左 |
| BREAK直前 → 脱出後 | `B=2 BC=1 G=2 X=0` → `B=2 BC=1 G=2 X=0` | 同左 |
| 偽のLOOPを持つDOの本体 → 条件後 | `F=1 FC=0 X=0` → `F=1 FC=1 G=3 X=0` | 同左 |
| 最終値 | `O=12113 TMP=0 X=0` | 同左 |
| 結果の保持 | 開始・BREAK後・偽条件後・最終の各点で `RESULT=701`, `RESULTS=sentinel259` | 同左 |

`O` は補助関数の呼出順を表す累積値です。最初のLOOP条件は1回目に評価され、BREAKした周回では評価されません。後のDOは1回本体に入り、偽の条件を1回評価して抜けています。ガードは3回評価され、危険関数は呼ばれていません。スキップされたLOOPの回を正常実行として数えません。各履歴は末尾の `C259_DONE` まで到達し、3本の履歴bytesは一致しました。

元の限定判定 `matched_scoped` は維持します。比較記録はPy側のOUTPUTLOGに関する通知を限定的に分類したうえで `MATCHED_FINITE` としています。Py側の終了コードは0、タイムアウトなしです。本家2回は5秒後もプロセスが生存し、その後に実行管理側が終了させたため、**自然終了は未観測**です。`C259_DONE` は終了命令の実行を直接追跡した記録ではありません。
