# Case196 PRINTPLAIN / PRINTSINGLE bounded review

20 observations in one instrumented fixture; Native twice, pinned public pyz once. Native raw logs reproduce byte-for-byte. Public comparison: raw/layout match 15/20; observable content, measured state, and helper evaluation count/order match 20/20. Five empty SINGLE cases show a real serialized line-lifecycle difference. This is not closure for all PRINT commands.

## Finding

C196_12-16: PRINTSINGLE with omitted nullable argument, PRINTSINGLEV "", PRINTSINGLES "", PRINTSINGLEFORM with omitted nullable argument, PRINTSINGLEFORMS "".

- Native body: `P><T\r\n`
- public body: `P>\r\n \r\n<T\r\n` (the middle line contains one ASCII space).

Native EmueraConsole.Print.cs:297-307 returns on null/empty before flushing the pending prefix. For nonempty SINGLE, it flushes pending text, appends a single display line, then refreshes. Both engines serialize prefix / target / tail as three lines for the five nonempty SINGLE conditions. For the empty conditions Native leaves prefix pending to join the tail, while public serializes the prefix, a blank-space line and the tail separately. This is a log-level lifecycle observation, not evidence about temporary-line replacement, input lifecycle, timing, glyphs, or actual paint.

PLAIN/PLAINFORM ordinary and empty examples agree on prefix/tail joining. PRINTLC/PRINTFORMLC short ASCII examples agree including padding: `lc` has 24 following spaces; `c1/2` has 22. This is specific to the copied configuration and font measurement environment, not a general column-width guarantee.

## Conditions and separate comparison axes

See conditions.json, CONDITIONS_TABLE.md and fixture.ERB. Nine ordinary cases cover all nine assigned commands, seven empty cases cover PLAIN and SINGLE families, four selected SKIPDISP cases cover PLAINFORM, SINGLEV, SINGLEFORMS and FORMLC. Each resets A/B, RESULT=701, RESULTS:0=sentinel, prints a pending `P>` prefix, executes the target, prints `<T` with PRINTL, then records state. SKIP conditions bracket only the target with SKIPDISP 1 / SKIPDISP 0.

COMPARISON.json retains each engine's raw condition block, exact layout rows including whitespace, observable content/value observations, state, and evaluation as separate fields.

- Raw: original BOM-bearing UTF-16LE logs retained; no line-ending/whitespace normalization. Segment hashes are explicitly UTF-16LE without a segment BOM. Complete log hashes include BOM.
- Layout: exact serialized rows and spaces, not a GUI layout capture.
- Value/content: observable target text after separating prefix/tail and CRLF. LC trailing ASCII padding is excluded only on this axis. Empty cases record absence of nonwhitespace content and record structural spaces separately. Internal argument values were not independently captured, so this axis cannot erase the empty SINGLE raw/layout difference.
- State: A, B, RESULT, RESULTS:0 only. Normal cases retain RESULT=701; SKIP cases show RESULT=0 after SKIPDISP 0, whose own side effect prevents attributing that change to PRINT. RESULTS:0 stays sentinel throughout.
- Evaluation: helper count A and digit-encoded order B. H(1),H(2) produce A=2/B=12. SINGLES T(1) gives A=1/B=1 and prints its returned `{ZZ196H(2)}` literally; SINGLEFORMS T(1) gives A=2/B=12 and expands it. Literal PLAIN/SINGLE preserve braces without calling helpers. All four selected SKIP cases show A=0/B=0 and no target output.
