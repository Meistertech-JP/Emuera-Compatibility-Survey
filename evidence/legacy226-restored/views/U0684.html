# Case201 HTML_ESCAPE / HTML_TAGSPLIT text contract

20 bounded conditions completed using identical fixture/config/empty-csv inputs: Native twice through the supplied CreateDesktopW harness; public once through root/run_public_pyz_verified.py. All 20 conditions match on raw, serialized layout, value, selected state and helper evaluation. The three complete BOM-bearing UTF-16LE application logs are byte-identical. This closes only the observed text contract in this fixture, not HTML GUI rendering or the complete command family.

## Observations

HTML_ESCAPE expression and method-as-command are paired for ordinary ASCII, empty, angle brackets, existing ampersand/entity text, and Japanese plus both quote characters (C201_01-10). Expression syntax is `ZZ201V '= HTML_ESCAPE(ZZ201S(1))`; method-as-command syntax is `HTML_ESCAPE ZZ201S(1)` without call parentheses. Expression returns into the assigned string variable and leaves RESULTS:0 unchanged. Method-as-command writes RESULTS:0 and leaves the separate value variable unchanged. Both preserve RESULT:0=701, RESULT:1=702, RESULT:2=703 and C=704 in these cases. The helper runs exactly once (A=1/B=1), including the empty input.

Observed escapes: `<a>` -> `&lt;a&gt;`; `&amp;&` -> `&amp;amp;&amp;`; Japanese stays Japanese, double quote -> `&quot;`, apostrophe -> `&apos;`. Existing entities are escaped again, not decoded.

HTML_TAGSPLIT C201_11-20:

- Ordinary Japanese/ASCII containing a lone `>` is a single unchanged token. Empty input returns count=0 and preserves all sampled destination slots.
- `pre<b>中</b><br>tail` separates into `pre`, `<b>`, `中`, `</b>`, `<br>`, `tail`, count=6. Adjacent actual tags introduce no empty text token.
- `&lt;b&gt;&amp;` remains one unchanged text token. Entities are neither decoded nor treated as actual angle brackets.
- `a<x q=">">b` separates into `a`, `<x q=">`, `">b`, count=3: the first `>` terminates a token even inside quotes. This is lexical separation, with no validation of HTML tag names or attributes claimed.
- `pre<b>ok<bad` sets RESULT:0=-1 and preserves sampled RESULTS:0-5. It does not partially copy the tokens preceding the unclosed `<`. The following STATE/END markers, later conditions and C201_DONE are present: this input did not stop execution in any run.
- A two-slot destination for `a<b>c</b>d` receives only `a`, `<b>`, while explicit C receives full count=5; RESULT:0 remains 701.
- `HTML_TAGSPLIT ZZ201S(3), ZZ201D:ZZ201N(2), RESULT:ZZ201N(1)` writes ZZ201D from element zero, preserves D3-D5, sets RESULT:1=3 and leaves RESULT:0=701. A=2/B=31 proves the source helper then the count-index helper ran, and the destination-index helper was omitted. No arbitrary index/side-effect behavior beyond this selected expression is claimed.
- Explicit count `RESULT:0` receives count=3 with a custom output array, matching the default count location while RESULTS:0-5 remain sentinel values.
- Source/output alias `HTML_TAGSPLIT RESULTS:0` reads the original `a<b>c` before overwriting RESULTS:0-2 with its tokens. RESULT:0 becomes 3; no helper runs. This is the tested string-source alias, not arbitrary reference aliases.
