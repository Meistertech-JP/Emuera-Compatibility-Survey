# ADDCHARA_DYNAMIC_CHARANUM_ORDER_20261113

## 比較条件

`ADDCHARA CHARANUM+10,CHARANUM+10` を同一 ERB・CSV・設定で Native v24 を2回、公開 PyEmuera 3.0.0 pyz を1回実行した。公開pyzは実行前後ともSHA-256 `8a7b3697b97155c4dc994c8349c6756bb0401000d3bbccd8e85ff046e3774b35`。 Nativeの画面入力は送っておらず、ログと標準出力・標準エラーだけを保存した。

## 観測

All three runs (Native twice and public pyz once) reached the completion marker. Each reported CHARANUM=0 before the command, CHARANUM=2 after it, NO0=10 and NO1=11. The second expression reads CHARANUM after the first addition, so this selected case confirms term-by-term evaluation with immediate character addition; pre-evaluating both terms at the initial state would produce 10 twice. Native raw logs are byte-identical. Public and Native observed outputs match in this finite case.

## 判定範囲

これはADDCHARAの該当条件に限った、動的引数評価順序の一致観測である。関数呼び出しの副作用や失敗後の部分状態など、別の評価条件へ一般化しない。
