# INRANGE・LIMIT・PRINTVW：保存された観測

[English](README.md) | [機械可読case](data/cases.jsonl)

本家 Emuera1824+v24 と PyEmuera の保存記録を、各条件とmodeに対応させた資料です。raw出力は保存bytesのコピー、UTF-8版は指定encodingによる可逆な読取り用変換です。原票・receipt・fixture・設定・実行物は含まず、この資料だけでは独立再実行できません。

## 命令形式の正常条件

INRANGEとLIMITは同じfixture・3 modeの共有batchです。各vectorは `A=0, B=0, RESULT=777, RESULTS=SENTINEL` から始まり、x・min・maxの3つのhelperが各1回、順序123で評価されます。次の値は命令直後のRESULTです。Native 2 modeの各値は一致しています。

| (x,min,max) | INRANGE 本家 / Py | LIMIT 本家 / Py |
|---|---:|---:|
| (3,4,8) | 0 / 0 | 4 / 4 |
| (4,4,8) | 1 / 1 | 4 / 4 |
| (8,4,8) | 1 / 1 | 8 / 8 |
| (9,4,8) | 0 / 0 | 8 / 8 |
| (3,8,4) | 0 / 0 | 8 / 8 |
| (4,8,4) | 0 / 0 | 8 / 8 |
| (8,8,4) | 0 / 0 | 4 / 8 |
| (9,8,4) | 0 / 0 | 4 / 8 |

逆転境界の不一致2件はLIMITのみです。Nativeの自然終了・終了codeは未観測で、有限条件を超える互換性は確定していません。親受入pendingは元票時点の記録です。

## helper評価中のゼロ除算

INRANGE・LIMITそれぞれのslot 1、2、3を別条件で記録。基準vectorは`(4,4,8)`ですが、該当helperは`C=0`で`1/C`を評価して値を返さないため、全引数が実際に渡ったとは限りません。slot 1／2／3の到達helper数は1／2／3、順序は1／12／123。到達時は`RESULT=777`、`RESULTS=SENTINEL`です。本家はゼロ除算、Pyは`E_ARITH`を診断し、形式は異なります。AFTER・DONEとエラー後の状態は未観測です。元の有限case判定は`matched_scoped`で、診断の全文一致を意味しません。

## PRINTVWの待機復帰

Native 2 modeは空のRichEditにReturnを1回、Py 2 modeはLF空行を1行入力。helperの評価前は`A=0, RESULT=5, RESULTS=BEFORE`、保存履歴に`17`の行があり、復帰後は`A=1, RESULT=9, RESULTS=AFTER`が各1回です。4件の`emuera.log`は同一bytesですが記録roleは別です。Pyのプロセスstdoutには入力promptがあり、`emuera.log`と同一bytesとは扱いません。Nativeの自然終了・終了code、GUI pixel、他のPRINTV条件は未確認です。
