# Saved observations: CALL/JUMP/EVENT, PRINT D and LIST owner

[日本語](README.ja.md)

This evidence set contains 28 recorded cases: 12 CALL/JUMP/EVENT, 6 PRINT D, and 10 LIST owner. The 19 typed targets in [target-priority.json](target-priority.json) were unconfirmed for paired raw and fixture in the inspected candidate indices at selection time. This is not evidence of absence elsewhere, complete coverage, reach or acceptance. Each case preserves the recorded target roles, condition, comparison, verdict and limitations in [index.json](index.json).

Each case has one recorded batch with Native-01, Native-02 and public-01. Source path identity and receipt bindings are retained per mode. Equal bytes or a shared role do not prove a shared or independent execution. LIST receipts do not declare case ID or mode; their derived fields explicitly say that the case evidence and mode-specific source path supply the binding. The other receipts also declare source condition and mode. The receipts do not declare the selected raw output; binding uses case evidence, the group manifest and saved readback. Derived receipts omit source paths, argv, process IDs and timestamps. The original full receipts, other outputs and complete parent review are not included. Fixture and config files are byte-identical source copies. The individual source-to-derived SHA crosswalk is held separately.

LIST case text labels the parent readback as a nonincluded shared group summary; its CALL/JUMP values are not attributed to individual cases. Uncalled LIST cases are not target reach. No state after fatal stop, Native natural exit or exit code follows from a runner return code. PRINT D records concern serialized output, not pixel or font equivalence. The inputs shown are those declared by each selected receipt; they are not a claim that all historical dependencies or omitted files are included.

Use Python 3.10 or newer. Before running the verifier, use an external hash utility to check the manifest against its SHA-256 obtained through a separate trusted channel, and check `verify.py` and `tools/file_set_manifest.py` against their hashes in that trusted manifest. Then run `python -B verify.py --manifest-sha256 <external-manifest-pin> --bindings-sha256 <external-bindings-pin>` using independently obtained pins. Integrity checks do not prove origin, execution, rights, or publication approval. The private source record and complete rights review are not included.
