The fixtures and native source imply that the first four conditions retain the initial value and `SD_INDEX` writes `INDEXED11`. Native pre-instruction markers also show the initial `PLAN_LOCAL_STRING`. This inference uses the fixture paths and `Instraction.Child.cs`, `Process.ScriptProc.cs`, and `ArgumentBuilder.cs` from the [reference distribution](../../vendor/emuera/README.md). A build record connecting the executable to those sources has not been verified.

The native log alone cannot distinguish a newline inside the value from wrapping at the display width. In the native source, `PrintStringBuffer.cs` splits display lines and `OutputLog` in `EmueraConsole.Print.cs` writes those lines. The native column therefore reports recorded characters and line boundaries; it does not present the concatenated string as a direct measurement. PyEmuera's value is an observation of a separate engine, not a direct measurement of native state. Read the state values in the original records with this display limitation in mind.
