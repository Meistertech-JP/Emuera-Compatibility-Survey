# Source and input provenance

`core.py` derives its expression validation, plan parsing, fixture generation, decoding, observation parsing and comparison functions from the survey v3 runner, SHA-256 `36dfbe0b38e78247e6dd0f55c16bc337b364bf5066c82247875f0f0c191b84c5`. The portable wrapper adds final-marker enforcement and offline comparison. `validator.py` derives from the v3 evidence validator, SHA-256 `5a03132d0c525d3450f6f4b0f2b11d0f6c0416e8b01afa5cdbc0ade466dd3fb9`; its module description was updated. `native.py` adapts the isolated-desktop and process-handle method used by the Native helper, SHA-256 `66fa869af7856f7a5b410a30c236640999e475f07b9ca85cf0e1225f5d280793`. The controller is an adaptation, not an unmodified historical runner.

`audit.py` adapts v3's whole-attempt semantic-replay approach to the portable expression controller's own v2 result schema. It rederives observations and verdicts from the portable plan and raw logs and requires a separately supplied seal hash; it is not a reader for the historical v3 attempt schema. The older v2 runner's reseal-based reuse is not used. Old portable v1 results lack the required input receipts and are refused for reuse.

`fixtures/representative-plan.json` retains the IDs, typed keys, and expressions for one case from the 29-case expression plan (SHA-256 `5e126af6beb841003dbaf47df23862fc5890b83476d870ce547b9f3daa5c919f`) and both cases from the two-case acceptance plan (SHA-256 `bef295dfb1ba18653f51e48f77f3a763db38c2057a9753d24e0531a4d6bb0375`). It replaces historical review references and internal planning text with a limited public-facing scope and explicit numeric observations. It is a derived plan, not the historical plan or an update to its adjudication. Results from a new run are new observations.

`fixtures/emuera.config` is an unchanged copy of the execution template, SHA-256 `f08f478f133fa2b1b0887d3a48934138860f3b13be623ecbba453ed85e9a11cc`. The retained Native ZIP SHA-256 is `fd0dd5b83ab3f929e69de0b9af739fa9bf785b6f510b30d11aaf44db35af182a`; it is distributed with notices in the project's `vendor/emuera/` bundle, not in the harness directory. PyEmuera is obtained separately. This record does not resolve all licensing questions or prove the source and executable are wholly identical.

The unmodified manual reference ERB hashes are: P35 `1706ef111d20f7c813a3dd8ab24142cb2607578c41f78986b9de69290d012a19`; P36 `2387f9b30142c4b338c770e5f4cd782505f0b2e757a685599ad8adf79da74d9f`; P38 `8b2bf27fed8c6131fa8a2a22a57522cf4ce846b5d16ac78f4951f72d81581471`. They are executed by the local-case controller, not the expression controller. The GUI input and capture approach adapts the earlier isolated-desktop probe and capture helper; only the cropped display is written. `RESULT_WRITE` derives its TOINT/TOSTR command approach from the `METHODCMD02` survey fixture, with explicit before/after values and OUTPUTLOG added; it is a new instrumented fixture, not an unmodified historical case. `ARGUMENT` is a new bounded missing-argument fixture.
