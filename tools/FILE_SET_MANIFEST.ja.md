# 配布用ファイル集合の SHA-256 台帳

[English](FILE_SET_MANIFEST.md)

`file_set_manifest.py` は、**将来確定する選定済みディレクトリ**それぞれの全通常ファイルの相対パス・サイズ・SHA-256 を記録し、その後の集合を照合します。名前付きルートを使い、通常のリポジトリ内容と Release アセットを別々に検査できます。同じ相対パスが異なるルートにある場合は別ファイルです。ルート全体を走査し、除外パターンや現在の candidate からの公開対象自動選定はありません。空ディレクトリはファイルではないため台帳に含みません。

このツールも生成する台帳も、公開適性・権利・機密情報・互換性の承認を意味しません。現時点の candidate は審査中です。後日、選定・監査したものを専用の staging ディレクトリに分け、内容を凍結してから使用してください。リポジトリに実際に含める `.git` 以外の集合と Release アセットの集合を明示してください。`.git`、内部資料、過去の失敗物を名前だけで自動除外する機能はありません。

## 使い方

Python 3.10 以上。以下のパスは利用者が用意する選定済みの例です。生成先は新規ファイルで、既存台帳は上書きしません。ここに掲載したコマンドは実行済みの最終凍結を意味しません。

```powershell
python -B tools/file_set_manifest.py create `
  --root repo=<選定済み通常ファイルのディレクトリ> `
  --root release=<選定済みReleaseアセットのディレクトリ> `
  --manifest <新規manifest.json>

python -B tools/file_set_manifest.py verify `
  --root repo=<同じ通常ファイルのディレクトリ> `
  --root release=<同じReleaseアセットのディレクトリ> `
  --manifest <manifest.json>
```

ルート名は英小文字・数字・`_`・`-` で、先頭は英小文字です。同名ルートの重複、同じ／入れ子のルートは拒否します。台帳に絶対ルートパスは保存されないため、異なる場所へ移しても同じ名前のルートとして指定できます。検証時は生成時と同じルート名・manifest の内外位置を指定します。フォルダー名に空白がある場合は `"repo=C:\path with spaces\repo"` のように引数全体を引用します。

manifest をいずれかのルート内に置く場合、その位置を台帳内に記録し、**その manifest 自身だけ**を集合から除外して循環参照を避けます。他の manifest やハッシュファイルは通常のファイルとして扱います。manifest の親ディレクトリは事前に用意してください。ルート外の manifest も使用できます。manifest 自体の SHA-256 や信頼できる署名が必要な場合は、別の信頼された記録で保管してください。

Windows の通常パスと拡張長パス `\\?\`、大小文字や短縮名などの別表記は、アクセス先の実体と祖先を OS に照会して判別します。異なる表記であっても親子ルートなら拒否し、同じ manifest の場合は実際の名前を基準に自己除外します。既存 manifest の記録上の綴りが異なる場合も、OS が同じファイルと確認できた場合に限り受け入れます。大小文字が異なるだけで同一と決めつけず、実際に別のファイルであれば同一扱いしません。以前の版がルート内 manifest をルート外（`null`）と誤記録した場合は安全のため自動修復せず拒否するので、新しい台帳を作成してください。

検証は欠落・余剰・サイズまたは SHA の変化を拒否します。絶対パス、`..`、逆スラッシュ、`CONIN$`・`CONOUT$` と拡張子付きも含む Windows の予約名・ADS を含む危険な台帳パス、JSON 重複キー、重複行、大文字小文字または Unicode NFC の名前衝突、ファイル／ディレクトリの衝突も拒否します。ルートとその先祖、および再帰的な対象内の symlink・Windows reparse point（ジャンクション含む）は拒否し、通常ファイル以外は読みません。エラーは終了コード1、成功は0です。

予約名の判定は全 OS で共通です。各成分を NFKC 正規化し、最初のドットより前の名前から末尾空白を除いて照合するため、`CON .txt` や `LPT9 . .txt` も拒否します。Windows 互換性のための保守的な規則であり、POSIX で通常ファイルとして有効な名前や、NFKC で予約名になる表記も拒否することがあります。一方、`CONSOLE .txt` や `COM10 .txt` など予約名に一致しない幹はこの規則では拒否しません。各成分末尾の空白やドットは別途拒否します。

`verify` は作成した manifest との一致を示します。manifest 自体を攻撃者が編集してハッシュを再計算できる場合、改ざんの真正性は検出できません。暗号署名ではなく、外部の信頼された manifest ハッシュや署名と組み合わせてください。ファイルの識別子・サイズ・更新時刻を前後確認しますが、並行書換えや OS の競合に対する完全なスナップショット保証ではありません。書換えを止めた staging で実施してください。プラットフォームによるシンボリックリンクの作成権限と reparse point の扱いは実環境で確認してください。

テストは候補ディレクトリで、対象を限定して実行します。

```powershell
python -B -m unittest discover -s tests -p test_file_set_manifest.py -v
```
